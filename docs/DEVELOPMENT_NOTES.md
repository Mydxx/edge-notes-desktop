# Edge Notes 开发笔记（通俗版）

> 写给"半年后的自己 / 接手的人"看：为什么这么做、坑在哪、怎么绕过去的。
> 不追求学术严谨，只保证看完能上手改。

---

## 0. 一句话说清这个软件是什么

一个**贴在屏幕边缘的笔记栏**：平时收起成 4 像素的细条，鼠标碰一下滑出来，写完自动存成本地 `.md` 文件。
没有云端、没有账号、没有同步——所有数据都是你自己的文件。

选择"贴边"而不是"普通窗口"的原因：普通窗口要么挡住内容，要么被别的窗口挡住；
贴边窗口可以做到"要用时 0.2 秒出现，不用时几乎不存在"。

---

## 1. 技术选型：为什么是 Electron

| 选项 | 为什么没选 |
|---|---|
| WinUI / WPF | 界面开发慢、跨平台无望、富文本（Markdown 预览）要自己造轮子 |
| Tauri | 体积小，但 WebView2 行为在不同 Windows 版本上差异大，边缘停靠/多窗口这类"系统交互"仍要写 Rust |
| Qt | 学习曲线陡、授权与打包麻烦 |
| **Electron** | 前端写界面最快、`BrowserWindow` 对"无边框 + 置顶 + 精确 setBounds"支持好、生态成熟 |

代价很直接：**装完占 300 MB 左右，安装包 115 MB**。对一个"便签"来说偏重，
但换来的是"两周内能做出可用产品"。如果哪天觉得太重，迁移到 Tauri 是可行路线（界面代码能复用大半）。

## 2. 窗口是怎么"贴"在屏幕边缘的

### 2.1 核心思路：不是"固定在边缘"，而是"整体移出屏幕"

窗口宽度始终是**面板宽度**（默认 350 DIP），收起时把它整体向右平移，只留 4 像素在屏幕里：

```
收起：窗口 x = 屏幕右边界 - 4      → 只露出 4px
展开：窗口 x = 屏幕右边界 - 350    → 整块出来
```

好处：
- 不需要两套窗口（细条 + 面板），也不需要在两者之间做"交接"，不会闪；
- 动画就是 16ms 一帧的 `setBounds` 平移，状态机只有四个状态，逻辑简单。

代价：**屏幕最右侧 4 像素的点击会被这条细条吃掉**（已写进已知限制）。

### 2.2 状态机

```
collapsed ──hover──> expanding ──动画结束──> expanded
    ^                    │                      │
    └──收起动画结束── collapsing <──指针离开────┘
```

关键规则：
- `expanding` / `collapsing` 期间**不响应新的触发**（否则会抖）；
- 收起不是立即的，有一个 `collapseDelay`（700/900/1200 三档），鼠标离开后延迟才收；
- 定时器到点时**再核对一次指针**——不核对就会出现"鼠标刚好回来但面板还是收了"的抽搐。

### 2.3 命中判定为什么放宽了 2px / 6px

- 触发条：真实鼠标在屏幕边缘很难精确停在某个像素上，左右各放宽 2px；
- 面板内侧：拖着调宽松手时，指针常停在面板内侧外 1~7px，如果按严格边界判定，
  会立刻被判"指针离开"然后收起——用户会觉得"刚拖完就自己跑了"。所以内侧放宽 6px。

## 3. 笔记是怎么存的

### 3.1 目录结构

```
D:\Edge Notes Data\            ← 默认非系统盘，可在设置里改
├── notes\
│   ├── 工作笔记.md            ← 文件名 = 标签名（改标签就改名）
│   └── 周报 (2).md            ← 同名笔记自动加序号
├── attachments\              ← 图片，正文里写 attachments/xxx.png
├── notes-index.json          ← 顺序、标题、文件名、上次打开的笔记、每篇的视图状态
└── edge-notes-settings.json  ← 面板设置
```

**为什么正文和索引分开？**
索引坏了可以丢掉索引、扫描 `notes/*.md` 重建；正文永远是最重要的东西，
不能因为一个 JSON 写坏就丢笔记。这条是设计底线。

**为什么文件名要用标签？**
最早是 `n-mvvd70gt-9990d0.md`，用户根本认不出哪个文件是哪篇笔记。
现在文件名就是标签，可以脱离软件直接用记事本打开、在资源管理器里搜。

### 3.2 写盘：为什么这么啰嗦

```ts
写 tmp 文件 → rename 覆盖正式文件
```
`rename` 在同目录是原子操作：要么旧内容、要么新内容，不会出现"写了一半"的半截文件。

再叠三层保护：
1. **600ms 防抖**：连续打字不会每敲一下就写盘；
2. **写盘目标在内容变更时就绑定**：切笔记时不会把 A 的内容写进 B 的文件；
3. **切走前同步补写 + 退出前同步补写**：`flushSync()`，并用 `frozen` 标记让"还在飞行的异步写"作废，
   否则可能被旧内容覆盖回去。

### 3.3 改标签 = 改文件名，最麻烦的地方在哪

不是 `rename` 本身，而是**时机**：

> 如果用户改标签的瞬间正好有一次异步写还没落盘，那次写用的是"旧文件路径"，
> 等它落盘时会把内容写到旧文件名上，于是磁盘上出现两个文件、内容不一致。

解决办法：**改名只发生在"刚写完盘"之后**。
- 改标签时，若当前笔记还有内容没落盘（写盘中 / 防抖窗口内）→ 先不改名，只改索引里的标签；
- 等那次写完成后，`writeNow()` / `writeSyncNow()` 里统一调 `syncFileName()` 对齐文件名。

其它细节：
- 非法字符 `\ / : * ? " < > |` → 换成 `-`（标签本身不改）；
- Windows 保留名 `CON/PRN/COM1…` → 前面加 `_`；
- 两篇同名 → `工作笔记 (2).md`，加序号时先给后缀腾长度，避免超出 63 字符上限；
- 老数据 `n-xxx.md` → 启动时一次性改名成标签名，失败就保持原名、下次再试。

## 4. 系统集成里那些"课本上不会写"的坑

### 4.1 开机启动：两个版本的教训

| 版本 | 做法 | 结果 |
|---|---|---|
| 0.10 | `app.setLoginItemSettings` | 未打包时**假成功**：回读说已开启，注册表里什么都没有，几秒后变回 false |
| 0.11 | 自己写 `HKCU\...\Run` | 功能真实生效，但**联想电脑管家反复弹"electron 试图开机启动"** |
| 0.12 | 写「启动」文件夹里的 `.lnk` | 用户可见可删，安全软件当"用户自己的启动项"处理，弹窗消失 |

学到的东西：
- 未打包的 Electron 在系统集成上会给你"看起来成功"的假象，**必须去系统里查真值**（注册表 / 文件系统）；
- 用户觉得"能用但一直弹窗"和"不能用"，后者体验更好。系统集成要选**用户看得见、可自己撤销**的方式；
- 判断"是否真的会启动"要看 Windows 的 `StartupApproved`（用户可能在"启动应用"里关过）。

### 4.2 置顶与 Z 序：`moveTop()` 不一定管用

需求："我点了浏览器，笔记工具就跑到下层，划到右边也看不见"。

第一版做法：展开时 `win.moveTop()`。实测系统 Z 序发现**没生效**（面板还是在普通窗口下面）。
原因：当前台窗口属于别的进程时，`SetWindowPos(HWND_TOP)` 的抬升会被前台窗口的激活顺序压回去。

可用做法："**瞬间置顶再取消**"：

```ts
win.setAlwaysOnTop(true)   // 进顶层
win.setAlwaysOnTop(false)  // HWND_NOTOPMOST：落到"普通窗口层的最上面"
```

它不抢键盘焦点（实测 `document.hasFocus() === false`），所以不会打断用户正在打的字。

还有一个隐藏 bug：抬层只发生在"收起→展开"那一瞬间，
如果面板**已经展开**、被浏览器压住了，指针回到面板上时什么都不会发生。
修法是轮询里加一条："已展开 + 指针在面板内 + 窗口没焦点 + 指针在动" → 重新抬层，
并且限流 600ms，避免每次移动鼠标都触发"置顶/取消置顶"导致窗口闪。

### 4.3 托盘单击的语义

原来的实现是纯 toggle：面板展开时点托盘 = 收起。结果是"我点了一下，它反而没了"。
改成：
- 看不见（隐藏 / 收起）→ 唤出；
- 只有在"确实看得见"时才收起。

菜单里再单独给一个"隐藏到托盘"，不跟唤出混在一起。

### 4.4 隐藏 ≠ 收起

- **收起**：窗口还在，只露 4px，鼠标一碰就回；
- **隐藏**：整个窗口 `hide()`，只剩托盘图标（任务栏里没有按钮，见 4.5）。

两者混在一起做，会导致"隐藏后鼠标贴边又把面板叫出来"的矛盾行为。
所以隐藏态额外加了一个**门闩**（`hoverWakeArmed`）：
隐藏那一刻指针若正好停在边缘，必须先移开再贴回来才算"主动召回"，否则会出现"刚藏起来就弹回来"。

### 4.5 任务栏里不该有它

常驻托盘的工具，任务栏按钮纯属噪音：收起时只剩 4px，用户却在任务栏看到一个 "Edge Notes"，
第一反应是"是不是有个窗口没关掉"。

两处改动：

- `new BrowserWindow({ skipTaskbar: true })`：窗口可见时也不占任务栏位置。Windows 上走的是
  `ITaskbarList::DeleteTab`，只删任务栏标签，Alt+Tab 仍能切到它，不影响"面板被呼叫"的路径。
- `minimize` 事件兜底：`minimizable: false` 只去掉最小化按钮，挡不住 Win+D /"显示桌面"
  这类直接 `ShowWindow(SW_MINIMIZE)` 的外部动作。最小化一发生就 `restore()` 再
  `setHidden(true)`，转成"隐藏到托盘"，让窗口对外只存在两种状态：贴在屏幕边缘，或完全藏起来。

`restore()` 不能省：对一个已经处于最小化状态的窗口直接 `hide()`，之后再 `showInactive()`
未必能把它拿回来（会出现"托盘点了没反应"）。

验证不用肉眼（三个可测信号）：

| 断言 | 证据来源 |
|---|---|
| 窗口可见时任务栏没有它 | UI Automation 枚举 `Shell_TrayWnd` 子孙按钮，清单里搜不到 "Edge Notes" |
| 最小化会自动变成隐藏 | `ShowWindow(hwnd, SW_MINIMIZE)` 后 `IsWindowVisible` = False，且 `IsIconic` = False（说明是 hide 而不是留在最小化态） |
| 隐藏后还能召回 | `SetCursorPos` 真实移动光标贴屏边 → `IsWindowVisible` 回到 True |

### 4.6 "隐藏后唤出变白板"到底是怎么回事

现象：点"隐藏到托盘"→ 再从屏幕边缘唤出，面板回来了，但里面只有窗口底色，
工具栏、笔记列表、输入框全都不见。看起来像应用崩了，实际上进程、DOM、React 全都活着。

定位过程和结论（这条比结论本身更有用）：

1. 先证明"不是渲染层的问题"：CDP `Runtime.evaluate` 读 `document.body.innerHTML`（4501 字符）、
   `.panel` 的 `getBoundingClientRect`（350×1020）、`opacity/visibility` 都正常；
   `Page.captureScreenshot` 抓出来的图**完整有界面**。
   → DOM 与渲染管线都好，问题在"窗口合成/呈现"这一层。
2. 再录屏对比：`CopyFromScreen` 抓同一块区域，只有底色。
   两边一对照，结论就很干净：**渲染层画了，窗口没把它贴到屏幕上**。
3. 根因：面板 96% 的时间停在屏幕外（收起只露 4px），Chromium 的遮挡判定会把这种窗口
   标成 occluded 直接停止出帧。从 `hide()` 恢复时 `showInactive()` 让窗口重新可见，
   但合成层没有重新提交，于是只有 `backgroundColor` 被画出来。

三层加固（缺一层都可能偶发）：

| 层 | 做法 | 为什么 |
|---|---|---|
| 关掉遮挡降频 | `app.commandLine.appendSwitch('disable-backgrounding-occluded-windows')` + `disable-renderer-backgrounding` | 从源头上不让 Chromium 因为"窗口在屏幕外"而停止出帧 |
| 显示后强制重绘 | `win.showInactive(); win.webContents.invalidate()` 收进一个 `showWithoutFocus()` | 直接把这个已知的"surface 没重挂"状态刷掉 |
| 落位后再刷一次 | `expand()` 动画结束回调里再 `invalidate()` | 滑入全靠 `setBounds` 推帧，整段动画可能一帧都没提交 |

验证方式（可复现、可量化）：用 preload 暴露的 `window.edgeNotes.setHidden()` 走**和按钮完全
同一条 IPC 路径**做"隐藏→贴边唤出"，每轮用 `CopyFromScreen` 抓 360×260，统计唯一颜色数：
空白面板只有底色（<30 色），正常界面稳定在 ~294 色。隐藏时长覆盖 0.7s / 2s / 5s / 20s，
8 轮 0 次空白。

踩过的坑：早期几轮测试"怎么都唤不出来"，日志里只有 `hidden-changed` 没有 `hidden-wake`。
原因是**用户正在用鼠标**，`SetCursorPos` 设好的位置立刻被真实鼠标覆盖，面板自然不展开。
教训：涉及真实鼠标的自动化，必须每轮校验"光标是否真的到了目标位置"，否则测出来的
"No wake" 是假故障。

### 4.7 拖标题栏换边（往左拖=停靠左侧）

需求："用鼠标往左拖然后松手就跳到左侧，往右同理。"

手势放在**标题栏**，不是整个面板：

- 面板里要选文字、要点按钮，大面积接管 pointer 事件会把这些都弄坏；
- 内缘已经是"拖宽"手势的地盘，再叠一个手势必然互相打架；
- 标题栏本来就没有可编辑内容，语义上就是"拖动窗口"的地方。

实现要点：

1. `pointerdown` 记下起点与当前 `side`，并 `setPointerCapture`（拖出面板也不会丢事件）；
   从按钮上按下的拖动直接放行给按钮（`target.closest('button')`），否则点设置会把面板甩走。
2. `pointermove` 算 `dx/dy`：`|dx| >= 24` 且 `|dx| >= |dy|` 才算"要换边"，
   方向就是目标侧（`dx < 0` → 左）。**不回中就不换**，手抖不会让面板翻面。
3. `pointerup` 才真正 `setSide(target)`：拖动过程中面板纹丝不动，松手才"跳"过去——
   这样中途反悔只要把指针拖回起点即可，不会误操作。
4. 拖动期间复用 `setResizing(true)`（主进程里就是"别自动收起"的开关），
   否则拖到面板外面超过 1.2s，面板会自己缩回去把拖拽打断。

提示：`dropSide` 只在"目标侧 ≠ 当前侧"时才会渲染出 `dropHint`——
目标侧贴一条 4px 强调色竖线，标题下方给一句"松开停靠到左侧/右侧"，
避免用户盲拖。

验证（两种输入通道都过一遍）：

| 断言 | 方式 |
|---|---|
| 往右拖松手 → 停靠右侧 / 往左拖松手 → 停靠左侧 | 真实鼠标 `mouse_event` 按住拖动 + 读 `edge-notes-settings.json` 的 `side`，两向各一次 |
| 拖动中真的出现提示、拖回起点提示消失 | CDP `Runtime.evaluate` 读 `.dropHint` 的 `className/textContent/getBoundingClientRect` |
| 标题栏按钮没被手势吃掉 | CDP `Input.dispatchMouseEvent` 点中 `#toggle-always-on-top` → 设置里 `alwaysOnTop` 翻转；再用真实鼠标复测一次 |
| 换边不影响宽度 | 整个过程 `width` 始终是 350 |

测试期间的另一个坑：PowerShell 里的 `SetCursorPos` 用的是**逻辑（DIP）像素**（屏幕只有 0~1706），
我一开始按物理像素写坐标（还乘了 1.5），点击直接飞到屏幕最右边，表现成"往左拖没反应"。
现在坐标一律用逻辑像素写，和 Electron 的 `screenX` 同一空间。

## 5. 测试是怎么做的（这部分最值钱）

### 5.1 不信"看起来对"，只信可测量的证据

| 断言 | 证据来源 |
|---|---|
| 窗口贴在屏幕边缘、不盖任务栏 | DWM `DwmGetWindowAttribute(9)` 拿物理可见矩形 + 工作区 |
| 面板在上面 / 在下面 | `EnumWindows` 枚举系统 Z 序，比较两个窗口的索引 |
| 鼠标贴边能展开 | PowerShell `SetCursorPos` 真实移动光标，再看状态 |
| Ctrl+Alt+N 能唤出 | `keybd_event` 发真实按键 |
| 开机启动真的生效 | 读「启动」文件夹里的 `.lnk` + `WScript.Shell` 解出 target |
| 安装包能装能卸 | 静默装到临时目录 → 查文件/快捷方式/卸载项 → 静默卸载 → 查残留 |

指标化以后，"1~3 物理像素"这种模糊问题也有结论：
窗口可见底边比工作区多 1~3 像素，是 DIP→物理像素两次取整的固有误差，
于是断言写成"越出量 < 2 DIP"——如果有人误用屏幕 `bounds` 而不是 `workArea`，
越出量会变成 70+ 像素，测试立刻红。

### 5.2 遇到过的最坑的三个测试问题

1. **锁屏导致"贴边不展开"**：`SetCursorPos` 在锁屏时静默失败，光标不动，测试以为功能坏了。
   后来固定做法：先移动光标再读回坐标，坐标不变就说明会话被锁。
2. **测试污染真实数据**：安装包冒烟测试忘了建临时数据目录，
   程序回落到用户真实目录 `D:\Edge Notes Data`（真的把 3 篇笔记打开了）。教训：**测试必须先建目录再启动**。
3. **回收站是异步的**：删除笔记后立刻断言"文件已消失"会偶发失败，
   改成轮询等待（最多 5 秒）。

## 6. 打包（第 06 轮）

- `electron-builder` + NSIS（中文界面、可选安装目录、桌面/开始菜单快捷方式）+ portable；
- 打包体积控制：`files` 白名单只要 `dist/`、`dist-electron/`、`package.json`，`node_modules` 一个都不进（渲染层已由 Vite 打成单文件）；
- 托盘图标在 asar 里读不到特殊路径，所以走 `extraResources` 放到 `resources/assets`；
- 便携版用 `PORTABLE_EXECUTABLE_DIR` 把数据放在 exe 旁边；
