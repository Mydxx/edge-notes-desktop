# 与前沿产品的差距分析

> 目的：老实说清"现在这东西和成熟产品差在哪、差多少、哪些是故意不做的"。
> 对照对象挑的是同类里做得最好的，以及"边缘停靠笔记"这个细分形态的代表作。

---

## 1. 对照对象

| 类别 | 产品 | 为什么拿来比 |
|---|---|---|
| 同形态（贴边笔记） | macOS **SideNotes**、Windows **Sticky Notes**、**OneQuick/Quicker 的侧边面板** | 形态最接近，直接可比 |
| 本地优先笔记 | **Obsidian**、**Logseq** | 同样是"本地 Markdown 文件"路线，能力上限的参照 |
| 云端笔记 | **Notion**、**语雀**、**印象笔记** | 生态/协作/同步的参照 |
| 轻量速记 | **flomo**、**Drafts**（iOS）、**Simplenote** | 输入体验与"低摩擦记录"的参照 |

结论先说：**在"贴边唤起 + 本地文件 + 零账号"这个交叉点上，我们不输；一旦跨出这个交叉点，差距是全方位的。**

---

## 2. 我们已经做到、且不落后的部分

| 能力 | 状态 | 说明 |
|---|---|---|
| 边缘唤起速度 | ≈ 持平 | 收起只占 4px，鼠标贴边 60ms 轮询 + 200ms 滑出，主观"即时" |
| 启动速度 | 略优 | 冷启动到可输入约 1.5s（Electron 基线），比 Notion/语雀桌面端快 |
| 数据归属 | **优于云端产品** | 就是磁盘上的 `.md`，文件名=标签，可被任何工具读写、可进 Git |
| 资源占用 | 中等 | 常驻 ~120MB 内存（Electron 基线），高于 Sticky Notes（UWP ~40MB） |
| 离线可用 | 完全离线 | 没有任何网络请求 |
| 干净程度 | 较好 | 无账号、无遥测、无广告；安装包无捆绑 |

## 3. 明确的差距（按"用户能感知"排序）

### 3.1 搜索（最痛的缺口）

- **现状**：只能看侧栏列表，最多 200 篇，靠标题认。
- **前沿**：Obsidian 全库即时搜索 + 正则 + 标签；flomo 有全文检索 + 时间轴。
- **差距**：没有全文搜索，笔记一多就只能靠文件名。这是**下一个最该补的功能**（甚至比同步更急）。

### 3.2 同步与多设备

- **现状**：单机单文件，换电脑要手动拷目录（设置里有"数据目录迁移"，但那是本机搬盘）。
- **前沿**：Notion/语雀实时同步 + 冲突合并 + 历史版本；Obsidian 靠 iCloud/Git/Syncthing 也能做到。
- **差距**：完全没有。**这是产品定位问题**：本地优先就意味着把同步交给用户（放进 OneDrive/Git 目录也能用），
  但至少应该做"检测到目录在云盘同步文件夹时给出提示"。

### 3.3 编辑器能力

| 能力 | Edge Notes | Obsidian/Notion |
|---|---|---|
| Markdown 语法高亮 | ❌（纯 textarea + 预览切换） | ✅ 实时双栏/所见即所得 |
| 图片粘贴 | ✅ | ✅ |
| 表格/待办/代码块渲染 | ✅（marked + 白名单净化） | ✅ 且可交互（勾选、表格编辑） |
| 反向链接 / 双链 | ❌ | ✅ 核心能力 |
| 标签 / 附件管理面板 | ❌ | ✅ |
| 导出 PDF/HTML/图片 | ❌ | ✅ |
| 版本历史 | ❌ | ✅（云端或插件） |

差距集中在"富交互"：我们是"写 Markdown 的记事本"，它们是"知识库"。

### 3.4 组织能力

- 没有文件夹/层级、没有标签筛选、没有收藏/置顶笔记、没有归档；
- 只有"一条平铺列表 + 拖动排序"（200 篇上限）。
- 前沿产品都有至少三层组织手段（库/文件夹/标签）。

### 3.5 安全与隐私

| 项 | 现状 | 前沿 |
|---|---|---|
| 落盘加密 | ❌ 明文 | 印象笔记有加密笔记；Obsidian 靠插件 |
| 应用锁 / 生物识别 | ❌ | 少数产品有 |
| 代码签名 | ❌（SmartScreen 会提示"未知发布者"） | 商业产品全部签名 |
| 自动更新 | ❌ | 商业产品全部有 |

代码签名与自动更新是"发布工程"的差距，不是功能差距，但对"敢不敢双击安装"影响很大。

### 3.6 平台覆盖

- 只有 **Windows x64**；
- 贴边交互是 Windows 特有的实现（`screen.getCursorScreenPoint` + `setBounds`），
  macOS 需要重做（那边有 `NSPanel`/`floating` 层级与 Space 行为），Linux 还要考虑 Wayland 限制。
- 前沿产品普遍 Win/macOS/移动端/Web 全覆盖。

### 3.7 工程成熟度

| 项 | 现状 | 成熟产品 |
|---|---|---|
| 单元测试 | ❌ 没有 | 都有 |
| E2E | ✅ 310 项真实系统断言（这是我们的强项） | 通常更多但多为隔离环境 |
| 静态检查 | 只有 `tsc`，无 ESLint | 完整 lint + 格式化 + CI |
| CI/CD | ❌ 手动 | 自动构建 + 签名 + 灰度发布 |
| 崩溃上报 | ❌（有本地日志） | Sentry 等 |
| 无障碍 | 部分（aria-pressed、焦点环） | 完整键盘导航 + 屏幕阅读器验证 |

## 4. 差距的"性价比"排序（如果要继续投入）

| 优先级 | 事项 | 理由 | 预估工作量 |
|---|---|---|---|
| 1 | 全文搜索（库内即时过滤 + 高亮跳转） | 笔记一多就没法用，投入小收益大 | 1~2 天 |
| 2 | 导出（Markdown/PDF/图片）与备份 zip | 用户最常问"怎么备份/拿出来" | 1~2 天 |
| 3 | 标签 + 文件夹/归档 | 组织能力从 1 维到 2 维 | 2~3 天 |
| 4 | 版本历史（本地快照，`.history/`） | 误删/误改的自救，本地实现不需要服务器 | 2 天 |
| 5 | 代码签名 | 消除"未知发布者"，需要证书成本 | 半天 + 证书 |
| 6 | 自动更新（electron-updater + 静态托管） | 分发体验 | 1~2 天 |
| 7 | 加密笔记（密码 + AES） | 隐私敏感用户 | 3 天 |
| 8 | 跨平台（macOS 优先） | 形态最需要重做的部分 | 1~2 周 |
| 9 | ESLint + CI | 工程卫生 | 半天 |

**不建议做的**：云端账号体系、实时协作、插件生态。这三件事一旦做，产品就从"低摩擦个人工具"变成"平台"，成本与维护是数量级上升，且和我们"本地优先、零账号"的定位冲突。

---

## 5. 一句话总结

> 我们做出的是"**在 Windows 上贴边即用、数据完全归自己**的笔记工具"，
> 在这一个点上是完整且经过真实系统验证的（310 项断言、真安装真卸载）；
> 但它是"个人工具"，不是"知识库平台"——搜索、组织、同步、加密、签名这些"平台能力"都还没有，
> 且这是**产品选择**而不是遗漏。要往上走，第一步应该是全文搜索，而不是加云同步。
