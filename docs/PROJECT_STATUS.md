### 与规格的两处实现差异（有意为之，已记录）

1. **状态机命名**：规格建议 `hidden / showing / visible / hiding / pinned_open`。实际实现为
   `collapsed / expanding / expanded / collapsing`，并把"固定展开"、"编辑器聚焦"、"拖动调宽"做成三个**独立的抑制标志**而不是状态。
   原因：三者可以任意叠加（例如边拖宽度边固定展开），做成状态会导致状态爆炸；作为标志更简单且互不干扰。语义与规格等价。
2. **指针检测方式**：没有使用渲染层的 `pointerenter/pointerleave`，而是主进程每 40ms 读取
   `screen.getCursorScreenPoint()` 并做几何命中判定。原因：窗口有 346px 在屏幕外，且窗口可能失焦或被遮挡，
   DOM 事件在这些情况下不可靠；这样也不需要全局鼠标钩子或原生依赖。
   **实测开销**：收起态下 4 个 Electron 进程 10 秒共 0.063s CPU（折合单核 0.63%、整机 0.04%）。

## 五-3、第 05 轮验收对照（UI 与视觉精修）

### 诊断结论（改前）

1. 头栏 38px 尚可，但塞了 5 个图标按钮，280px 宽度下标题只剩约 40px；
2. 编辑区 flex 撑满，占比正常，但保存状态挤在头栏；
3. 设置按钮偏多：清空/退出属于低频操作却常驻头栏；
4. 280px 时头栏临界，有挤压风险；
5. **没有设计 Token**，存在 `#dfe3ec` / `#1b202b` / `#13161d` 等硬编码色值与散落数值；
6. 无重复控件；宽度是"只读展示 + 拖动手柄"，属展示+操作；
7. 展开/收起状态只能靠视觉判断，未加额外状态文案（保持安静）；
8. **没有 `:focus-visible` 样式**，键盘用户看不出焦点位置。

### 改版内容

- 头栏收敛为 3 个常显图标：置顶 / 固定展开 / 设置；
- 新增 30px 底栏承接「保存状态 + 清空 + 退出」，清空由 hover 隐藏改为常显文字按钮；
- 建立完整 Token 体系（颜色/间距/圆角/字号/结构尺寸），组件只引用变量；
- 补全 `:focus-visible` 焦点环，所有按钮补 `aria-label`；
- 设置弹层新增「自动收起」三档，宽度上限收敛到 600。

### 本轮踩到并修掉的两个坑

1. **`var(--font-body)` 未定义导致整条 `font` 简写失效**，正文字号一直停在继承来的 12px——字号切换测试直接把它抓了出来（"14.5px → 16px" 的断言最初是 "12px → 12px"）。
2. **`--user-data-dir` 会被 Chromium 从 `process.argv` 里吞掉**，导致"测试用显式目录时不要自动选盘"的守卫失效，测试实例一度被重定向到 `D:\Edge Notes Data`、读到真实设置而失败。改为判断 `userData` 是否已被外部改写（可靠信号），测试隔离恢复。

## 五-6、Markdown 预览 + 图片粘贴（方案 B）

用户选择「方案 B：Markdown + 图片」，按此实施。目标是让便签能写 Markdown、能直接粘贴截图，
但**不放弃纯文本可读性**（文件仍是 UTF-8 文本，可用记事本打开），也不引入联网能力。

### 实现

| 部分 | 做法 |
|---|---|
| 存储 | `edge-notes-note.txt` → `edge-notes-note.md`；启动时若只有旧 `.txt` 就改名为 `.md`（内容不动）；数据目录迁移也会带上旧文件 |
| 编辑/预览 | 头栏眼睛图标切换；编辑区**保持挂载只做隐藏**，避免卸载未受控 textarea 丢掉正文与光标 |
| 渲染 | `marked`（GFM + 单换行转 `<br>`）→ `DOMPurify` 净化 → 再把 `attachments/…` 改写成自定义协议 |
| 图片粘贴 | `paste` 事件取 `items`/`files` 里的图片 → IPC 写盘 → 光标处插入 `![](attachments/xxx.png)` |
| 图片读取 | 自定义协议 `edgenote-media://local/attachments/<file>`，`protocol.handle` 只解析附件目录下的**单层文件名**；CSP 仅放行该协议 + `data:` |
| 拒绝项 | 外链图片不加载（预览里显示"外链图片已阻止"）；SVG 不收；单张 > 10 MB 拒绝；`<script>`/`onerror` 等经净化剔除 |

### 验收（真实运行）

| 项 | 证据 |
|---|---|
| Markdown 渲染 | 预览里 `h1/strong/code/li×2/blockquote` 全部正确，编辑区隐藏 |
| XSS 净化 | 粘贴 `<img src=x onerror=…><script>…</script>` 后：`script` 元素 0 个、`[onerror]` 0 个、`window.__xss` 未被写入 |
| 图片粘贴 | **真实剪贴板位图 + 真实 Ctrl+V** → 正文出现 `![](attachments/img-….png)`，附件落盘 393 bytes |
| 图片加载 | 预览 `<img>` 走自定义协议，`naturalWidth=72`（与写入的位图一致） |
| 目录穿越 | `edgenote-media://local/attachments/..%2F..%2Fedge-notes-note.md` → 加载失败 + 主进程 `attachment-denied` |
| 外链图片 | `![](https://…)` → 显示阻止提示，`img[src^=http]` 数量 0 |
| 旧文件升级 | 只有 `.txt` 的目录启动后生成 `.md`、`.txt` 消失、内容不变（18 字） |

### 本轮踩到并修掉的两个坑

1. **预览图片一直 `naturalWidth=0`**：不是协议问题（探针里 `new Image()` 同 URL 能加载 32×32），
   是我给 `<img>` 加了 `loading="lazy"`，切到预览瞬间图片被浏览器推迟加载。去掉懒加载，并把断言从
   "元素存在"改成"解码完成（`complete && naturalWidth>0`）"。
2. **改数据目录时笔记没跟过去**：`data-location.ts` 里还写着旧文件名 `edge-notes-note.txt`，
   迁移只搬了设置文件。修正为搬 `.md`，并兼容带上遗留的 `.txt`。

### 已知取舍

1. 预览里的链接**不打开**（避免渲染层跳转/联网），保留视觉提示；需要跳转时再评估是否走系统浏览器。
2. 笔记里手写的 `<script>` 会被净化掉，用户看不到原样文本——这是"内容当不可信 HTML"的必然结果。
3. 图片只按原尺寸显示（`max-width:100%`），没有点击放大。
4. 附件不会随笔记自动清理：删掉正文里的引用不会删文件，需要手动清 `attachments`。

## 五-7、三条设计细节落实情况

用户提出三点建议：浅色主题不要做成"普通白色网页"、Markdown 要有编辑/预览双模式、图片必须作为本地资源统一管理。逐条落实：

| 建议 | 之前 | 现在 |
|---|---|---|
| 浅色不做成网页白 | 底色 `#f6f7f9`、浮层纯白 `#ffffff`、强调色 `#2f6fed`（就是"把黑改成白"） | 暖米白 `#f7f3ec` 纸感底色、浮层 `#fdfaf5`、暖灰分隔线 `#e4dccd`、暖近黑文字 `#2b2721`、低饱和墨蓝强调 `#526d8a`；窗口首帧底色同步 |
| 编辑/预览双模式 | 有切换按钮，但模式不记忆 | 模式写入设置、重启沿用；**Ctrl+E** 双向切换；切换前先算好 HTML（不闪空白帧） |
| 图片本地资源管理 | 附件在 `attachments\`，但改数据目录时**不跟着搬**（真 bug） | 迁移（含首次自动选盘）会把 `attachments` 整目录复制并逐文件校验；附件被删时预览显示「图片缺失：xxx」 |

### 量化验证（不是"看着还行"）

- 底色 `rgb(247, 243, 236)` ≠ 纯白；正文对比度 **13.42:1**、次要文字 **3.43:1**（`test:visual` 里有断言，注入计算而非人工目测）；
- 迁移测试里先造一个 `attachments/probe.png`，迁移后断言新目录里同名同大小存在；
- 缺图提示用"进预览前主动核对附件是否存在"实现（`checkAttachments` IPC），**不依赖 `<img>` 的 error 事件时序**——上一版靠事件，实测会漏。

### 本轮又抓到两个真问题

1. **开机启动写不进注册表**：`setLoginItemSettings` 只写 `Run` 项时，如果该应用在 Windows「启动应用」里被标记过，系统按"未启用"处理，回读 `openAtLogin=false`——测试正确地报了失败。修法是同时传 `enabled`（改写 StartupApproved 启用位）。
2. **像素级触发条判定再次因为换色失效**：探测器写死了"蓝色主导"，这次强调色降饱和后 `B-R` 不足阈值。这说明**用颜色识别自家控件本身就是错的**——已把左右两侧都改为按 `bounds` 硬断言（可见宽度 = 4 DIP），像素值只作为 `console.log` 参考。

## 五-8、最后一轮质量优化

五项针对性优化，均以"先查现状、只改真问题"为前提。

| 项 | 改前 | 改后 | 验证 |
|---|---|---|---|
| 文字可读性 | 次要文字 3.4:1（不达 AA）；占位文字 2.2:1 | 浅色 muted `#8b8272`→`#75695a`（5.5:1 实测）、占位 `#8f8471`；深色 muted 3.3:1→5.9:1 | `test:visual` 用 WCAG 相对亮度**逐色计算**：浅色 text 13.42 / dim 5.49 / muted 4.84 / accent 4.85；深色 text 15.17 / dim 7.03 / muted 5.91 |
| 附件清理 | 无 | 设置里「图片附件 → 清理…」：统计未被正文引用的文件数量与体积 → 确认 → `shell.trashItem` **移入回收站**；取消不动 | 断言：展示"1 个（8 B）"、取消后文件仍在、确认后只移走未引用的、被引用的保留 |
| 迁移完整性 | 只比文件大小 | **SHA-256 逐文件比对 + 文件数量核对**；失败回滚已写入文件、不写指针；错误按 ENOENT/ENOSPC/EACCES 等翻译 | 断言：3 个文件哈希全一致；目标路径非法 → 迁移失败且原笔记与指针未被改动 |
| 开机启动 | 回读 `openAtLogin`，开发模式下时真时假 | 未打包时**明确报告不支持**（`supported:false` + 原因），拒绝写入；打包后仍走官方 `setLoginItemSettings`，并区分 `enabled`（已写入）与 `active`（系统真会启动，读 `executableWillLaunchAtLogin`） | 断言：未打包 `supported=false`、尝试开启被拒且设置里不留假状态 |
| 图片放大 | 无 | 预览点图片 → 全窗口遮罩放大；Esc / 点击任意处关闭（无新依赖） | 断言：lightbox 内 `src` 走自定义协议、`naturalWidth>0`；Esc 后节点消失 |

### 这一轮最有价值的发现：开机启动在开发模式下是"假成功"

实测证据（独立探针，直接调 Electron 官方接口）：

- `setLoginItemSettings({openAtLogin:true, path: electron.exe, args:[appPath]})` 之后，`getLoginItemSettings()` 返回 `openAtLogin:true`、`executableWillLaunchAtLogin:true`、`launchItems:[{name:'electron.app.Electron', …}]`；
- 但同一时刻 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 里**没有任何对应项**，几秒后回读又变回 `false`。

也就是说：未打包时"写入成功"只是一个短暂的自读数，注册表里根本没落地。之前的实现会把这个 `true` 当成成功并写进设置文件 —— 正是"伪造成功状态"。现在改为：未打包 → `supported:false`，UI 置灰并给出原因，`setLaunchAtLogin` 直接抛错，启动时还会把历史遗留的 `true` 清掉。

### 已知限制

1. **开机启动只能在打包版验证**：本机没有可用的安装包，`isPackaged` 分支的注册表落地未实测（第 07 轮打包后需补验）。
2. **附件清理不做"多笔记交叉引用"**：当前只有一篇笔记，未被本笔记引用的文件即视为可清理。
3. **图片放大是"看"不是"编辑"**：没有缩放拖动、旋转、另存为。
4. **迁移只处理 attachments 的一层文件**：与附件协议白名单保持一致，更深层目录不识别。

## 七、开发中发现并修复的缺陷

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 收起定时器触发瞬间鼠标刚好回到面板，面板"收一半又弹回" | 定时器只管 fires，不再核对指针 | 定时器回调里再核对一次指针，在面板内就放弃本次收起 |
| 2 | 拖完宽度松手，0.7 秒后面板自己收起 | 宽度取整后指针常停在内缘外 1~7px，被判为"离开" | 面板命中区内缘额外放宽 6px（触发条仍是 2px） |
| 3 | 与另一个同名 Electron 应用共用 userData 与单实例锁，一方启动另一方直接退出 | 包名相同 | 显式 `app.setName('Edge Notes Desktop')` 并改包名 |
| 4 | 退出瞬间可能被仍在飞行中的异步写覆盖最新内容 | 同步补写与异步写竞争 | `frozen` 标记让异步写让位 |
| 5 | 真实鼠标 E2E 偶发失败（真人同时在用机器 / 焦点抢占） | 物理动作被抢占 | 物理动作带有限次重试，状态判定仍为硬断言；阶段切分改按日志下标 |
| 6 | 换侧是瞬移，观感生硬 | 布局变化一律 `setBounds` 落位 | 可见态换侧改 220ms 平移；拖动调宽仍即时跟手（拖动不能有动画延迟） |
| 7 | 拖动/置顶测试期间收起计时被静默抑制 | `Page.bringToFront()` 会让 Chromium 把焦点落到编辑框，而编辑框聚焦按设计抑制收起 | 测试在置前后显式 `blur()`，并把"编辑框未持焦点"做成断言；延迟测量前也清焦点 |
| 8 | "拖动期间不收起"断言把松手后的正常收起也算进去 | 断言按读取日志的时间窗判断，边界含糊 | 改为按 `resizing-changed` 的 true→false 区间精确界定 |
| 9 | 渲染进程崩溃后窗口变成一个没有任何 UI、也无法点击退出的空白面板 | 只记了日志，没有恢复路径 | 先重置抑制标记再自动 `reload()` 一次；再次崩溃则 `app.quit()`。**已用强杀渲染进程实测**：`renderer-reload` 后界面与 IPC 均恢复，笔记数据仍在 |
| 10 | 界面加载失败（例如漏了 `npm run build`）时只有空白窗口 | 失败只写日志 | 主框架加载失败时显示一页可读的中文提示（含错误码与修复方法） |
| 11 | 拖动窗口时指针捕获丢失会导致"面板再也不自动收起" | `resizing` 标记只由 pointerup 释放 | 窗口失焦时释放；渲染进程崩溃时连同 `editorFocused` 一起重置 |
| 12 | 打开设置浮层后收起、再展开时浮层还挂着 | 浮层状态是纯 React state | 面板真正收起后自动关闭（只在发生过展开→收起时触发，不影响收起态下打开） |
| 13 | 4px 触发条常驻满饱和蓝，长期挂在屏幕右缘偏刺眼 | 直接用强调色做边框 | 静息态 55% 透明度，鼠标靠近 / 面板展开时恢复满亮度（纯 CSS，无额外状态） |

## 八、未完成 / 已知限制

1. **ESLint 未配置**（第 01 轮遗留，需批准的依赖安装）。
2. **目录名未改**：`Rename-Item` 因 IDE 持有目录句柄被拒；关闭 IDE 后一条命令即可改为 `edge-notes-desktop`。
3. **150% 缩放下的 1~3 物理像素**：用 DWM 可见矩形实测，窗口可见底边比工作区底边多出 1~3 物理像素（任务栏高 72 物理像素，因此不会真正遮挡）。
   根因是 Electron 只能按整数 DIP 设置窗口尺寸，DIP→物理像素存在两次取整；试过"非整数缩放时少 1 DIP"，系统会再次进位回去，属于平台固有的亚像素误差，不做无依据的补偿。
   测试里改为用物理像素守卫"越出量 < 2 DIP"，一旦有人误用屏幕 `bounds` 而非 `workArea`，越出量会变成 70+ 像素并立即失败。
4. **多显示器 / 分辨率切换未实测**：本机单屏。已实现 `display-added/removed/metrics-changed` 重贴边，但无实测证据；面板固定停靠主显示器，未持久化 `displayId`。
5. **`sandbox: false`**：preload 引用了共享模块，未打包成单文件；`contextIsolation` 与受限 IPC 仍生效。
6. **IME 组合输入未单独实测**：文本插入走的是浏览器输入管线，未专门验证中文输入法组合态。
7. **开机启动未实现**：需写 `HKCU\...\Run`，属于系统级改动，留待第 05 轮确认后处理。
8. **4px 触发条会拦截屏幕边缘该处 4px 的点击**（"移出屏幕"方案的固有代价）。

9. **Tab 键在文本框里仍是切换焦点**，不插入制表符（保留键盘可导航性）；如需插入可用 `-webkit` 之外的组合键方案，属可选改进。
10. **设置弹层是浮层**，会盖住正文（无遮罩层），符合"轻量、不打断"的取向。
11. **280px 已是布局下限**：底栏三项（状态/清空/退出）刚好不溢出，再加控件就需要收进设置。
